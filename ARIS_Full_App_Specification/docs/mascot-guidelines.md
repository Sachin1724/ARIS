# Mascot Guidelines

Use one consistent fluffy lavender 3D character with stable silhouette, proportions and face. Approved states: welcome, good_conditions, conditions_changing, poor_air_quality, thinking, listening, speaking, device_disconnected, data_uncertain and success.

Drive state from structured backend/UI state. Invalid data must never map to a “good” expression. The mascot cannot imply medical certainty or causal attribution. Home uses a larger mascot; Ask ARIS uses a smaller avatar; connection flow uses supportive guidance; data screens prioritize charts. Screen readers should not announce decorative animation repeatedly; state must also be text/icon.
